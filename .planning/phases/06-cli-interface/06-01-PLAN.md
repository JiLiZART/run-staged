```rust
use std::{path::PathBuf, process};

use clap::Parser;

#[derive(Parser)]
#[command(version, about, long_about = None)]
struct Cli {
    /// Path to the config file (overrides auto-discovery)
    #[arg(long)]
    config: Option<PathBuf>,

    /// Suppress success summary output
    #[arg(long)]
    quiet: bool,

    /// Run on modified (not staged) files instead of staged files
    #[arg(long)]
    unstaged: bool,

    /// Exit 0 when no staged files or no patterns match
    #[arg(long)]
    allow_empty: bool,
}

#[tokio::main]
async fn main() {
    let cli = Cli::parse();

    // D-04: resolve relative --config paths against CWD (not git root) before
    // handing to lib::run. Absolute paths pass through unchanged.
    let config_path = cli.config.map(|p| {
        if p.is_relative() {
            std::env::current_dir()
                .expect("cannot determine current directory")
                .join(p)
        } else {
            p
        }
    });

    if let Err(e) = fast_staged::run(config_path, cli.unstaged, cli.allow_empty, cli.quiet).await {
        eprintln!("error: {e}");
        process::exit(1);
    }
}
```

Notes / decision references:
- D-01: clap derive, no new deps. Uses `Cli::parse()` (sync, exits process internally for `--help`/`--version`/parse errors).
- D-04: CWD-anchored resolution lives in `main.rs`, not `lib::run`, to keep the lib free of env side-effects.
- D-05: Strict unknown-flag rejection is clap's default — no `allow_external_subcommands` or `allow_hyphen_values`. Exit code 2 for parse errors is automatic.
- D-06: `#[command(version, about, long_about = None)]` reads CARGO_PKG_VERSION + CARGO_PKG_DESCRIPTION (added in Task 1).
- D-07: Long-only flags. clap auto-provides `-h` / `-V` aliases — those are kept as Unix-standard.
- snake_case field names auto-convert to kebab-case flags (`allow_empty` -> `--allow-empty`). Pitfall 3: do NOT write `#[arg(long = "allow_empty")]` — that would create a non-standard `--allow_empty` flag.
- Pitfall 2: `PathBuf::from(str)` is infallible; existence check happens inside `load_config` and surfaces as `AppError::ConfigNotFound` (exit 1, not exit 2). This is intentional per D-02/D-03.
